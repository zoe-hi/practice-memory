# 经验捕手｜前端页面布局与功能交互规格 v2

> **状态：**已确认，作为下一阶段前端实现的产品依据。  
> **范围：**页面布局、用户操作、状态变化与页面跳转；本文件不规定 API、数据库或代码目录。  
> **Demo 约束：**现场只演示一段语音走完全链路；产品页面与信息架构保留“活动中可持续补充原始记录”的完整设计。

## 1. 产品主线与对象

```text
一次活动
  ├─ 原始记录：活动中补充的语音片段、文字补充
  └─ AI 复盘：根据原始记录追问并整理
       └─ 经验卡：用户确认后进入「我的」和相应主题库
```

页面不得把“一场活动”“一条语音”“一张经验卡”当成同一对象。

| 对象 | 用户含义 | 生命周期 |
|---|---|---|
| 活动 | 例如一次亲子共读活动 | 开始记录 → 待整理 → 复盘 → 已沉淀 |
| 原始记录 | 活动中留下的语音或文字 | 可补充、检查、修正；进入复盘后修改需重置复盘 |
| 经验卡 | 对一次实践的结构化总结 | AI 草稿 → 用户编辑确认 → 正式经验 |

## 2. 全局布局与视觉规则

### 2.1 移动端页面骨架

```text
┌─────────────────────────┐
│ 状态栏                  │
├─────────────────────────┤
│ 可选：页面顶部栏         │
│  返回      标题      状态 │
├─────────────────────────┤
│                         │
│ 可滚动内容区             │
│                         │
├─────────────────────────┤
│ 可选：固定主操作按钮     │
├─────────────────────────┤
│ 一级底部导航（仅主页面） │
└─────────────────────────┘
```

- 使用现有手机壳宽度与奶油色背景；不重建一套视觉风格。
- 一级页为：`记一下`、`主题库`、`我的`，固定显示底部导航。
- 流程页为：`待整理`、`AI 复盘`、`经验卡确认`、`保存成功`，使用顶部返回栏，不显示底部导航，避免用户误离开未完成流程。
- 主操作使用荧光绿或深墨绿的圆角大按钮；次操作使用浅底描边按钮。
- 内容卡统一使用圆角、深色描边、轻投影；不要把经验呈现成“标准答案”。

### 2.2 可复用视觉组件

| 组件 | 用途 | 关键交互 |
|---|---|---|
| `TopBar` | 流程页顶部栏 | 左侧返回；右侧显示当前状态 |
| `BottomNav` | 三个一级入口 | 切换主页面；录音中禁用 |
| `VoiceSummary` | 当前活动的语音归纳 | 展开/收起已录语音列表与时长 |
| `RecordMic` | 大麦克风按钮 | 点击开始，再次点击结束 |
| `PrimaryAction` | 当前步骤的唯一主动作 | 不满足前置条件时禁用 |
| `SourceCard` | 原始文字/语音材料 | 展示、编辑或展开转写 |
| `ExperienceField` | 一项经验卡字段 | 草稿状态下可编辑，确认后只读 |
| `ThemeCard` | 主题库首页入口 | 进入对应主题详情 |
| `DecisionSheet` | 决策支持底部抽屉 | 覆盖当前主题页，不离开页面 |

## 3. 页面规格

## A. 记一下：活动中的快速记录

### A1. 空活动

**目的：**让实践者在现场低负担地开始留下判断。

布局从上到下：

1. `VoiceSummary`：`语音归纳`，副文案 `已录制 0 条语音`；展开时显示“还没有录音”。
2. 中部大麦克风。
3. 提示文案：`点击开始语音记录`。
4. 说明：`录音内容默认仅自己可见`。
5. 文字补充输入框：`改用文字补充`。
6. 禁用的主按钮：`活动完成，去整理`。
7. 底部导航。

### A2. 录音中

```text
点击麦克风
→ 请求麦克风权限
→ 中心显示时长、录音动画
→ 再次点击麦克风
→ 停止本段录音
```

- 录音过程中禁用底部导航、活动完成按钮与模式切换。
- 拒绝麦克风权限时，保留当前页面，提示用户允许权限或改用文字。

### A3. 已记录状态

```text
停止一段录音
→ VoiceSummary 显示「已录制 N 条语音」
→ 展开列表显示：语音 1、语音 2……、波形和时长
→ 中心文案变为「点击继续补充一段」
```

- 文字补充仍可输入。
- 有至少一条语音或非空文字时，`活动完成，去整理`可用。
- 点击主按钮进入 B 页。
- 离开后再返回，应恢复同一场未完成活动及已保存内容。

### A 页跳转

```text
A1 空活动 → A2 录音中 → A3 已记录
A3 ──活动完成，去整理──→ B 待整理
底部「主题库」→ G 主题库首页
底部「我的」→ F 我的
```

## B. 待整理：检查原始记录

**目的：**让用户先掌握、修正原始事实，再让 AI 介入。

布局：

1. 顶栏：返回、标题 `待整理`、状态 `待整理`。
2. `文字内容`卡片：显示文字补充；为空时显示 `暂无文字补充`。
3. 标题 `语音记录`。
4. 多条 `SourceCard`：`语音记录 1…N`、时长和三个图标操作。
5. 提示卡：`你可以先检查原始内容，确认无误后再交给 AI 进行复盘整理。`
6. 底部固定主按钮：`AI 复盘`。

### B1. 每条语音的三种操作

| 图标 | 名称 | 行为 |
|---|---|---|
| 声波 / 麦克风 | 转文字 | 展开转写文本；用户可编辑并保存 |
| 笔 | 修正 | 重新录制，替换当前这一条语音，不新增编号 |
| 垃圾桶 | 删除 | 弹出二次确认；确认后删除该条，列表重新编号 |

转写展开状态：

```text
语音记录 2
  [转写文字，可编辑]
  [保存修改]
```

### B2. 返回与重置规则

```text
点击左上返回
→ 保存当前活动
→ 回到 A3 记一下
→ 可以继续补充语音或文字
```

若 AI 复盘已经开始，用户再改文字补充、删除/修正语音或修改转写，必须提示：

```text
修改原始记录会重置当前 AI 问答和经验卡草稿，是否继续？
```

- 确认：清空复盘对话和草稿，返回 B 页待重新复盘。
- 取消：不保存本次修改。

### B 页跳转

```text
B ──返回──→ A3
B ──AI 复盘──→ C AI 复盘
```

## C. AI 复盘：面向经验字段的动态追问

**目的：**不是闲聊，而是补足经验卡缺失的关键信息。

布局：

1. 顶栏：返回、标题 `AI 复盘`。
2. 原始记录摘要：`原始记录 · N 段语音`，显示一段简短摘要。
3. 说明：`我只问对经验有帮助的问题，一次一个。`
4. 对话流：AI 问题卡、用户文字/语音回答卡，按时间顺序排列。
5. 底部输入区：主按钮 `语音回答`，文字图标切换为文字输入。

### C1. AI 的工作边界

AI 按实际缺失信息追问，不在页面上写死题数；后端最多追问五次。已有明确来源的信息不重复问，信息已足够时可提前成稿。追问围绕：

1. 发生了什么；
2. 做了什么调整及原因；
3. 观察到的结果；
4. 哪些部分似乎有效；
5. 反思、局限；
6. 注意事项、适用条件；
7. 仍待验证的问题。

### C2. 对话结束

```text
AI 判断信息足够
→ 显示提示：
「信息已经足够。我把它整理成一张经验卡片，
保留了不确定的地方，请你确认。」
→ 显示「生成经验卡片」
→ 进入 D 经验卡确认
```

### C 页跳转

```text
C ──返回──→ B（不修改原始材料时保留当前复盘）
C ──生成经验卡片──→ D
```

## D. 经验卡确认：AI 草稿由人确认

**目的：**让用户拥有最终解释权；未确认前不是正式经验。

布局：

1. 顶栏：返回、标题 `经验卡片`。
2. 状态标签：`AI 已整理完成 · 请你确认`。
3. 卡片头：主题、日期、经验标题。
4. 7 个可编辑字段。
5. 说明：`可修改内容，没有确认前不会产生经验卡片。`
6. 底部固定主按钮：`确认保存经验卡片`。

字段固定为：

| 序号 | 页面标题 |
|---|---|
| 1 | 发生了什么 |
| 2 | 我做了什么调整 |
| 3 | 观察到的结果 |
| 4 | 似乎有效 |
| 5 | 反思与局限 |
| 6 | 注意事项 / 适用条件 |
| 7 | 还不确定 |

旧原型里的“支持经验 / 反例 / 正例”等标签不进入正式页面；统一使用“经验卡”。

### D 页跳转

```text
D ──返回──→ C（保留草稿）
D ──确认保存经验卡片──→ E 保存成功
```

## E. 保存成功

布局：

1. 成功图标与标题 `已保存！`。
2. 文案：`这条经验已进入「我的」，并归入下面的主题。`
3. 新经验摘要卡。
4. 两个出口：
   - 主按钮 `去我的看看`；
   - 次按钮 `去主题库发现更多经验`。

```text
E ──去我的看看──→ F 我的
E ──去主题库发现更多经验──→ G 主题库首页 / 对应主题
```

## F. 我的：个人实践记录

布局：

1. 贡献者信息头图。
2. 两个统计卡：`待处理`、`已整理`。
3. `最近留下的经验`时间线。
4. 底部导航。

### F1. 待处理记录

| 活动状态 | 点击后的恢复页面 |
|---|---|
| 记录中 | A3 记一下 |
| 待整理 | B 待整理 |
| 正在复盘 | C AI 复盘 |
| 待确认经验卡 | D 经验卡确认 |
| 处理失败 | 失败提示与重试入口 |

### F2. 已确认经验

```text
点击时间线卡片
→ 经验详情页
```

详情页为只读，需展示完整字段与说明：

```text
经验来源：由一线实践者记录并确认；单次经验，不代表普遍规律。
```

## G. 主题库：按实践问题组织经验

### G1. 首页

首页固定展示四张主题卡，且每个主题都要有封面、详情与预置演示经验：

1. 儿童活动引导：现场注意力、情绪与秩序；
2. 志愿者协作：分工、沟通与现场配合；
3. 阅读推广：选书、共读与参与度；
4. 社区活动运营：报名、动员与现场组织。

首页还包括：

- 产品 Hero 区；
- 新手快速开始入口；
- 右下角 `决策支持`悬浮按钮；
- 底部导航。

### G2. 主题详情

```text
点击主题卡
→ 主题详情页
→ 该主题的经验列表
→ 点击任意经验卡
→ 经验详情页
```

每个主题至少有预置演示经验卡；它们用于展示产品结构，不能伪装为用户刚刚录制生成的内容。

本次现场 Demo 新生成的经验默认归入 `儿童活动引导`。

## H. 决策支持：把历史经验带回现场

**入口：**主题库首页悬浮按钮，或主题详情内“带着这个主题去问决策支持”。

```text
点击入口
→ 从底部弹出抽屉
→ 背景仍保留当前主题页面
```

布局：

1. 可拖动的抽屉把手；
2. 标题 `决策支持`；
3. 当前困扰的语音 / 文字输入；
4. 结果区域；
5. 底部语音输入与文字切换。

结果必须按以下顺序展示：

```text
当前困扰
→ 来自过往经验（最多 3 张）
→ 可参考的历史做法与已记录限制
→ 留给现场的判断
```

决策支持不是聊天机器人、不是标准答案。它只把已有经验、适用条件和边界带回来，由用户完成当前判断。

```text
记一下 A1 空活动
  → A2 录音中
  → A3 已记录（可持续补充）
  → B 待整理
  ↔ A3 继续补充
  → C AI 复盘
  → D 经验卡确认
  → E 保存成功
  ├→ F 我的
  └→ G 主题库

F 我的
  → 待处理活动
  → 恢复 A3 / B / C / D
  → 已确认经验详情

G 主题库
  → 四个主题详情
  → 经验详情
  → H 决策支持底部抽屉
```

## 5. 本次 Demo 的演示路径

完整产品支持活动中的多次补充；但现场演示只走一段语音：

```text
记一下
→ 录制语音记录 1
→ 待整理：查看并修正转写
→ AI 复盘
→ 编辑经验卡
→ 确认保存
→ 我的 / 儿童活动引导主题
```

Demo 不现场演示第二段语音，也不把删除、替换多段语音作为验收阻塞项。

## 6. 原型遗留内容的处理

| 原型内容 | 正式决定 |
|---|---|
| 固定 `3/3` AI 问题数 | 删除，改为动态追问 |
| 支持经验 / 反例 / 正例 | 删除，统一为经验卡 |
| 6 个视觉字段 | 调整为 7 个字段 |
| 四主题但部分无内容 | 四个主题均有预置演示卡 |
| 原始记录修改不影响 AI 草稿 | 修改时必须提示并重置复盘 |
